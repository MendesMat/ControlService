# AGENTS.md

Instructions for AI coding agents working on this repository. This file is the entry point: read it completely before any change, then open the guide or workflow that matches the task. People should start with [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

## Project

Control Service is an ERP for service companies and the owner's public portfolio. Everything that reaches GitHub must look like the work of a careful professional team.

- **Back-end:** `backend/ControlService`, .NET 10, Clean Architecture with four projects, Minimal APIs, PostgreSQL, .NET Aspire.
- **Business rules:** `docs/` (Portuguese) is the source of truth. `docs/03-regras-de-negocio.md` and `docs/04-permissoes.md` define behavior and the exact user-facing messages.
- **Technical decisions:** `docs/adr/` (English). Accepted ADRs are binding.
- **Status:** the back-end skeleton is ready; the first slice being built is sign-in, users and per-screen permissions ([roadmap](README.md#roadmap)).

## Non-negotiable rules

1. **Never push to `main`, and never merge a pull request unless the owner explicitly asks for that pull request.** `main` is protected by a ruleset. Work on a branch, open a pull request, wait for CI and hand it over: [git and pull requests](docs/agents/workflows/git-and-pull-requests.md).
2. **Never weaken the safety nets:** no force push to `main`, no `--no-verify`, no editing or disabling the ruleset, CI checks, analyzers or `TreatWarningsAsErrors`, and no skipping or deleting failing tests to get a green build. Fix the cause.
3. **Commit only with the repository's identity** (`Matheus Mendes <104966152+MendesMat@users.noreply.github.com>`, set in the local git config). Never commit with a personal e-mail, and do not add `Co-authored-by` or "generated by" lines.
4. **Never commit secrets:** passwords, tokens, connection strings with credentials, certificates. Use user secrets or environment variables.
5. **Never change the machine's security settings**, such as trusting certificates (`dotnet dev-certs https --trust`), firewall or antivirus rules. Give the owner the command to run.
6. **Never delete data or published resources without an explicit request:** the Docker volume `controlservice-postgres-data`, GitHub repositories, releases, branches of other people.
7. **Never invent business rules.** If `docs/` does not answer the question, ask the owner. Do not fill gaps with assumptions presented as rules.
8. **Never rewrite an Accepted ADR.** Write a new ADR that supersedes it: [record a decision](docs/agents/workflows/record-a-decision.md).
9. **Package versions live only in `Directory.Packages.props`.** Project files reference packages without a version.
10. **Stay in scope.** One pull request per logical change. Report unrelated problems instead of fixing them silently.

## Talking to the owner

The owner is a junior developer who knows the business from end to end. **Reply in Brazilian Portuguese.** Explain the intent behind technical choices, ask descriptive questions with a recommendation and its trade-off, and report outcomes faithfully (including failures). Details: [communication guide](docs/agents/guides/communication.md).

## Commands

Run from `backend/ControlService`:

```bash
dotnet build ControlService.slnx
```

```bash
dotnet test --solution ControlService.slnx
```

```bash
dotnet run --project src/ControlService.AppHost
```

The last one needs Docker Desktop running. Environment details, ports and Windows/PowerShell pitfalls: [local environment guide](docs/agents/guides/local-environment.md).

## Definition of done

A change is done when all of these are true:

- [ ] Build has no warnings and no errors, and all tests pass locally.
- [ ] New behavior has tests; domain rules have unit tests written first.
- [ ] Architecture rules hold (the architecture tests pass).
- [ ] `docs/` and ADRs reflect any change in behavior, contract or decision.
- [ ] The change is in a pull request with the template filled in, and CI is green.
- [ ] The owner received a summary in Portuguese: what changed, how it was verified, what is left.
