# ADR-0004: Use built-in OpenAPI generation with the Scalar UI

- **Status:** Accepted (2026-09-23)
- **Date:** 2026-09-23
- **Scope:** Back-end

## Context

The API needs a machine-readable contract and an interactive page to explore it. For years this was done with Swashbuckle. Starting with .NET 9, the ASP.NET Core templates no longer include Swashbuckle; OpenAPI documents are generated by the first-party `Microsoft.AspNetCore.OpenApi` package instead.

## Decision

We will generate the OpenAPI document with **`Microsoft.AspNetCore.OpenApi`** (`AddOpenApi` and `MapOpenApi`) and expose an interactive reference with **Scalar** (`Scalar.AspNetCore`, `MapScalarApiReference`).

- The interactive UI is enabled in the Development environment and in the public demo environment.
- The OpenAPI document is also generated at build time (`Microsoft.Extensions.ApiDescription.Server`) and committed under `docs/api/openapi.json`, so the contract can be reviewed in pull requests.
- Endpoint summaries, descriptions and examples are written in English; user-facing error messages stay in Portuguese (see ADR-0009).

## Alternatives considered

- **Swashbuckle.** Still works, but it is no longer part of the default templates.
- **NSwag.** Mature and able to generate clients, but heavier than needed.

## Consequences

- The contract is generated from the endpoints themselves, so it cannot drift from the code.
- Changes to the contract become visible in code review through the committed `openapi.json`.
- Scalar is a third-party UI; replacing it later does not affect the generated document.
